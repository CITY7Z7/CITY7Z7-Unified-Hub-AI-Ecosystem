# AGENTS.md — Правила и протокол работы AI-агентов с проектом

> **Статус документа:** Нормативный  
> **Область действия:** Единая экосистема Lab + ToolHub (Full Stack AI Workbench & Execution Engine)  
> **Язык разработки:** TypeScript / React 19 / Fastify / Node.js & Bun / Prisma / Dexie.js

---

## 1. Архитектурные принципы экосистемы

1. **Единая когнитивно-исполнительная экосистема:**
   - **Lab (`apps/lab` или `client`)** — пользовательский клиент-воркбенч для интерактивного взаимодействия с моделями (OpenAI, Gemini, Ollama, Groq, OpenRouter), визуализации деревьев диалогов, редактирования кода в Monaco, подсчёта токенов, стриминга голоса и управления контекстом.
   - **ToolHub Core API (`apps/api`)** — высокопроизводительный сервер на Fastify с базой данных SQLite/Prisma (`hub.db`), диспетчером раннеров (Bun, Node, Bash, Python), пулом MCP-процессов, версионированием инструментов и REST/Swagger API.
   - **ToolHub Admin (`apps/admin`)** — административная консоль для управления деревом категорий навыков, тестирования в Playground, мониторинга логов аудита и фоновых процессов MCP.
   - **Unified SDK (`packages/sdk` / `shared/sdk`)** — протокольный шлюз взаимодействия `<hub>listTools(...)` и `<hub>callTool(...)`, общий для Lab и внешних агентов.

2. **Сохранение поведения превыше рефакторинга (Behavior First, Refactor Second):**
   - Любое архитектурное объединение обязано сохранять 100% существующего функционала обоих продуктов.
   - Не удалять и не модифицировать сигнатуры публичных API эндпоинтов:
     - `GET /*` — навигация агента по каталогу категорий.
     - `POST /*` — вызов инструмента агентом.
     - `GET /prompt` — компиляция системного промпта со списком корневых ресурсов.
     - `/admin/api/*` — административные вызовы для настройки системы.
   - Не ломать локальную модель хранения Lab (Dexie.js в IndexedDB) и клиентский ReAct-цикл исполнения шагов инструментов.

3. **Локальность и безопасность (Local-First & Principle of Least Privilege):**
   - Lab работает по модели Local-First: пользовательские ключи API и история диалогов хранятся в IndexedDB браузера и никогда не передаются на сервер без явного запроса пользователя к выбранному провайдеру.
   - ToolHub изолирует выполнение скриптов инструментов во временных системных каталогах ОС (`os.tmpdir()`), исключая загрязнение рабочей директории приложения.
   - Разделение уровней доступа: `x-agent-password` для вызова навыков агентами, `x-admin-password` для административных операций.

## 2. Размещение основных компонентов

| Компонент | Расположение исходников | Назначение |
|---|---|---|
| **Lab Frontend** | `apps/lab/src` (или `src/lab`) | Чат-студия, ветвление диалогов, управление токенами, рендеринг LaTeX/Monaco, Voice Engine |
| **ToolHub Admin** | `apps/admin/src` | Веб-консоль администратора: дерево категорий, управление раннерами, MCP-пул, аудит логов |
| **ToolHub API** | `apps/api/src` | Fastify-сервер, OpenAPI/Swagger (`/docs`), обработчики шлюзов MCP и Federation, диспетчер запуска кода |
| **Database Layer** | `prisma/` & `apps/api/prisma/` | Схема SQLite `schema.prisma`, миграции, сиды раннеров и промптов `seed.ts` |
| **Shared SDK** | `packages/sdk/` (или `src/lib/toolhubSdk.ts`) | Клиентский класс `HubSDK`, безопасный парсинг XML-тегов `<hub>`, авто-санитизация JSON |
| **Документация** | `docs/` | Архитектурные спецификации, ADR, инвентарь компонентов, OpenAPI, карты миграции |

## 3. Правила изменения кода

1. **Строгая типизация TypeScript:**
   - Все новые функции, интерфейсы и пропсы компонентов должны иметь явные типы.
   - Избегать неконтролируемого использования типа `any`. При работе с динамическими JSON-пэйлоадами инструментов использовать generic-типы `unknown` с валидацией или сужением типов (type narrowing).
2. **Изоляция изменений:**
   - Изменения в модуле ChatArea или Store не должны влиять на независимость ToolHub API.
   - Изменения в контракте Fastify API должны обязательно синхронизироваться со спецификацией OpenAPI (`docs/api/`) и классом `HubSDK`.
3. **Комментарии и самодокументируемость:**
   - Код должен быть богато и ясно прокомментирован.
   - Для всех ключевых функций, хуков и контроллеров писать JSDoc/TSDoc с описанием входных аргументов, возвращаемых значений и возможных исключений.
4. **Запрет на потерю функционала:**
   - Не удалять i18n ключи локализации (`en`, `ru`, `zh`). При добавлении новых UI элементов обновлять все поддерживаемые языковые файлы.

## 4. Правила изменения документации

1. **Параллельная фиксация:**
   - Документация обновляется **одновременно с кодом**, а не после него.
   - При перемещении или переименовании любого файла агент обязан зафиксировать старый и новый путь в `docs/migration/path-map.md`.
2. **Архитектурные решения (ADR):**
   - Любое фундаментальное решение (выбор схемы хранения, изменение транспортного протокола, смена пакетного менеджера) оформляется в `docs/architecture/decisions/ADR-XXX-name.md`.
3. **Обновление инвентаря:**
   - Добавление новых модулей, страниц или внешних интеграций должно немедленно отражаться в `docs/inventory/components.md`.

## 5. Правила запуска и проверки

1. **Среда исполнения:**
   - Node.js >= 20.x, Bun >= 1.2.x.
   - Единый пакетный менеджер: **Bun** (с поддержкой `bun install`, `bun run build`).
2. **Команды сборки и проверки:**
   - `bun run db:generate` — генерация Prisma Client.
   - `bun run db:push` — применение схемы БД SQLite.
   - `bun run build` — компиляция всех фронтенд-приложений и API.
   - `bun run typecheck` или `tsc -b` — валидация типов без генерации бандла.
3. **Проверка API:**
   - Проверка доступности системного промпта: `curl -H "x-agent-password: 123" http://localhost:3000/prompt`
   - Проверка корня категорий: `curl -H "x-agent-password: 123" http://localhost:3000/`

## 6. Критические зависимости

- `@prisma/client` & `prisma` — доступ к SQLite базе данных `hub.db`.
- `fastify`, `@fastify/cors`, `@fastify/swagger`, `@fastify/static` — серверная основа API.
- `dexie`, `dexie-react-hooks` — клиентская БД диалогов и дерева контекста.
- `zustand` — реактивное управление глобальным состоянием чата, провайдеров и параметров инструментов.
- `@monaco-editor/react` — ядро редактора кода VS Code для просмотра и изменения скриптов и сниппетов.
- `@lenml/tokenizer-gemini` & `js-tiktoken` — клиентский расчёт лимитов токенов контекстного окна.

## 7. Запрещённые действия

- ❌ **Запрещено** коммитить файлы с секретными ключами, реальными паролями или токенами (файлы `.env`, реальные ключи OpenAI/Gemini/Anthropic).
- ❌ **Запрещено** удалять оригинальные уведомления об авторских правах и лицензии AGPL-3.0.
- ❌ **Запрещено** изменять формат XML-тегов `<hub>listTools(...)` и `<hub>callTool(...)`, так как на них завязаны системные промпты и парсеры ответов LLM.
- ❌ **Запрещено** внедрять тяжёлые фоновые службы (например, внешние Docker-демоны) в качестве обязательного требования для локального старта.
- ❌ **Запрещено** заменять работающий нативный код заглушками (mock) или удалять неиспользуемые с точки зрения агента фрагменты без явного подтверждения.

## 8. Обязательные проверки перед завершением задачи

Перед тем как заявить о завершении любой итерации:
1. Выполнить компиляцию всех модулей (`bun run build` или `tsc -b`).
2. Убедиться в отсутствии синтаксических ошибок и ошибок линковки модулей.
3. Проверить целостность карты путей `docs/migration/path-map.md`.
4. Сверить поведение системы с чек-листом из `docs/testing/baseline.md`.
5. Убедиться, что обновлён отчёт `docs/final-report.md` (на финальном этапе).
