## 2. Рассмотренные подходы к Git

### Вариант 1: Слияние через `git subtree` / `git filter-repo`
- Позволяет сохранить плоские графы обоих репозиториев с переносом истории коммитов в подпапки `apps/toolhub` и `apps/lab`.
- **Ограничения в текущем окружении:** В рабочей среде разработки AI Studio сессия стартует в отдельном контейнере без привязки к внешним git-репозиториям как remotes.

### Вариант 2: Чистая монорепозитарная интеграция с сохранением метаданных (ВЫБРАННЫЙ ВАРИАНТ)
- Формирование новой чистой ветки объединённого проекта, в которой история коммитов исходных проектов подробно задокументирована в истории репозитория и ADR.
- Исходные коммиты логически разделяются по этапам:
  1. `baseline` — фиксация измерений и реверс-инжиниринга.
  2. `docs` — создание исчерпывающей спецификации и AGENTS.md.
  3. `architecture` — утверждение ADR и структуры монорепозитория.
  4. `merge` — безопасный перенос и связывание компонентов.
  5. `verify` — пост-мерж верификация и финальный отчёт.

---

## 3. Решение

Принять Вариант 2 с фиксацией ссылок на исходные репозитории и сохранением оригинального авторства кода.
