> **Статус документа:** Архитектурная спецификация  
> **Система:** Lab + ToolHub Unified Full Stack Ecosystem  
> **Версия:** 2.0.0

---

## 1. Концепция объединённой экосистемы

До объединения проект существовал в виде двух физически разделённых репозиториев:
1. `Talos-popcorn/toolhub` — сервер выполнения и оркестрации навыков с собственной веб-админкой (`apps/admin`).
2. `Talos-popcorn/lab` — пользовательский фронтенд-воркбенч (`🧪lab`), в коде которого (`src/lib/toolhubSdk.ts`, `useChatStore.ts`, `ContextSidebar.tsx`) уже была заложена нативная поддержка ToolHub как внешнего бэкенда по адресу `http://localhost:3001`.

**Объединённая система** ликвидирует искусственное разделение, превращая проект в единый, самостоятельный, локально-развёртываемый Full Stack комплекс с единым управлением жизненным циклом (зависимости, запуск, сборка, конфигурирование).

## 2. Потоки данных (Data Flow)

### 2.1. Поток выполнения автономного агента (ReAct Loop)
1. Пользователь в **Lab Studio** включает переключатель ToolHub в правой панели `ContextSidebar`.
2. Перед вызовом LLM клиент `HubSDK` выполняет запрос `GET /prompt` с заголовком `x-agent-password`.
3. Сервер формирует актуальный системный промпт со списком корневых папок (`{{AvailableResources}}`) и инструкциями по вызову через `<hub>...</hub>`.
4. Lab подмешивает промпт ToolHub в общий системный контекст и отправляет запрос в выбранную LLM (OpenAI, Gemini, Ollama и др.).
5. Во время стриминга ответа LLM обнаруживает потребность в инструменте и выдаёт: `<hub>listTools("/folder")</hub>` или `<hub>callTool("/folder/tool", {...})</hub>`.
6. Lab перехватывает закрывающий тег `</hub>`, останавливает стриминг и передаёт команду в `HubSDK`.
7. `HubSDK` выполняет `GET /folder` или `POST /folder/tool`.
8. Сервер ToolHub исполняет скрипт в изолированном временном каталоге, записывает аудит в `ExecutionLog` и возвращает результат в JSON.
9. Lab сохраняет шаг в `ToolStep` (в IndexedDB), форматирует результат в виде `HUB_RESULT: ...`, добавляет его в историю диалога и запрашивает у LLM следующий шаг.
10. Когда модель выдаёт финальный ответ без тегов `<hub>`, цикл завершается.

### 2.2. Поток администрирования
1. Администратор открывает `/admin/` в браузере.
2. Вводит мастер-пароль админа. Клиент сохраняет пароль в `localStorage` и отправляет `x-admin-password` во всех запросах к `/admin/api/*`.
3. Вкладка **Categories**: создание категорий, добавление скриптов инструментов, тестирование с отображением JSON Schema.
4. Вкладка **Runners**: конфигурация шаблонов среды исполнения скриптов (Bun, Bash, Python).
5. Вкладка **Processes**: мониторинг пула активных MCP-процессов, принудительное завершение зависших процессов.
6. Вкладка **Logs**: аудит задержек (latency), статусов выполнения, IP-адресов вызывающих агентов и пэйлоадов.

## 3. Решение конфликтов совмещения

1. **Маршрутизация портов и префиксов:**
   - Ранее ToolHub API слушал порт 3001, а Lab работал отдельно на 5173 (или Cloudflare Pages).
   - В целевой архитектуре **единый Fastify сервер** обслуживает:
     - Порт 3000 (по умолчанию)
     - `/` — статика и PWA воркбенча Lab.
     - `/admin/*` — панель администратора ToolHub Admin.
     - `/api/v1/*` и корневые `/*`, `/prompt` — агентские API-маршруты.
     - `/admin/api/*` — административные эндпоинты.
     - `/docs` — документация Swagger UI.
2. **Конфликт относительных URL:**
   - В Lab по умолчанию был прописан `toolhubUrl: 'http://localhost:3001'`.
   - В объединённой системе адрес по умолчанию становится относительным или конфигурируемым (автоматически указывает на текущий хост `window.location.origin` при пустом значении), что устраняет необходимость настройки CORS при локальной разработке.
3. **Хранение данных:**
   - Конфликта между базами данных нет:
     - ToolHub использует реляционную SQLite базу `hub.db` на сервере через Prisma ORM.
     - Lab использует клиентскую базу IndexedDB `LabDB` в браузере через Dexie.js.
   - Разделение зон ответственности сохраняется на 100%: приватные пользовательские диалоги и персональные ключи API не передаются в серверную БД ToolHub, оставаясь в браузере пользователя.
