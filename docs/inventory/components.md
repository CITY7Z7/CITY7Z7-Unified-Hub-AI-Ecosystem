# Каталог компонентов и карта зависимостей (Component Catalog)

> **Статус:** Нормативный справочник  
> **Охват:** Все модули, библиотеки, хранилища и интерфейсные блоки экосистемы Lab + ToolHub

---

## 1. Карта компонентов

### Компонент: ToolHub Fastify Core (API Server)
* **Что:** Центральный backend-сервер ToolHub.
* **Где:** `apps/api/src/index.ts`
* **Назначение:** Предоставление REST API для агентов и админки, Swagger UI, запуск скриптов раннеров, шлюзование MCP и федерации.
* **Зависит от:** `fastify`, `@fastify/cors`, `@fastify/swagger`, `@fastify/static`, `@prisma/client`, `child_process`, `mcp-helper.ts`, `mcp-pool.ts`, `SDK/JS/sdk.ts`.
* **Кто использует:** `apps/admin` (через `/admin/api/*`), `Lab` (через `HubSDK`), внешние LLM-агенты (через HTTP).
* **Вход:** HTTP-запросы с заголовками `x-agent-password` / `x-admin-password`, JSON-пэйлоады инструментов.
* **Выход:** Результаты выполнения скриптов, дерево категорий с JSON-схемами, системный промпт, Swagger документация.
* **Внешние интеграции:** Локальные раннеры (Bun, Bash, Python, Node), удалённые хабы (Federation), внешние MCP-серверы по stdio.
* **Критические ограничения:** Работает в локальной ОС пользователя; запускает скрипты в `os.tmpdir()`. Требует защиты паролем в открытых сетях.

---

### Компонент: MCP Pool & Helper
* **Что:** Подсистема управления долгоживущими MCP-процессами.
* **Где:** `apps/api/src/mcp-pool.ts`, `apps/api/src/mcp-helper.ts`
* **Назначение:** Запуск stdio-серверов протокола MCP (Model Context Protocol), кэширование списка инструментов, переиспользование процессов (stateful mode) и сборка мусора (graceful shutdown).
* **Зависит от:** `child_process.spawn`, JSON-RPC протокол.
* **Кто использует:** `apps/api/src/index.ts`.
* **Вход:** Команда запуска MCP (например `npx -y @modelcontextprotocol/server-filesystem`), аргументы, переменные окружения.
* **Выход:** Список инструментов в формате ToolHub, результаты выполнения методов через JSON-RPC.
* **Критические ограничения:** Должен корректно отслеживать зомби-процессы и перехватывать сигналы завершения сервера (`SIGINT`/`SIGTERM`).

---

### Компонент: Database Layer (Prisma SQLite)
* **Что:** Реляционное хранилище метаданных инструментов, категорий, раннеров и аудита.
* **Где:** `prisma/schema.prisma`, `prisma/seed.ts`, файл `hub.db`.
* **Назначение:** Персистентное хранение дерева навыков, настроек, версий кода инструментов и логов вызовов.
* **Зависит от:** `sqlite`, `@prisma/client`.
* **Кто использует:** `apps/api/src/index.ts`.
* **Вход:** DDL/DML запросы от Fastify-контроллеров.
* **Выход:** Типизированные сущности `Category`, `Tool`, `Runner`, `SystemSetting`, `ExecutionLog`.
* **Критические ограничения:** SQLite работает в файловом режиме (один процесс записи, множественное чтение). Очистка старых логов снабжена троттлингом (30 секунд) для предотвращения `SQLITE_BUSY`.

---

### Компонент: ToolHub Admin UI
* **Что:** Веб-панель управления и администрирования навыков.
* **Где:** `apps/admin/src`
* **Назначение:** Визуальное редактирование категорий, создание/отладка инструментов, мониторинг логов и процессов.
* **Зависит от:** `React 19`, `react-router-dom` v7, `Tailwind CSS`, `@monaco-editor/react`, `@radix-ui/*`, `sonner`.
* **Кто использует:** Администратор / разработчик навыков.
* **Вход:** Данные от `/admin/api/*`.
* **Выход:** Интерактивный UI с префиксом маршрута `/admin/`.
* **Критические ограничения:** Защищён экраном ввода мастер-пароля админа (`x-admin-password`).

---

### Компонент: Lab Chat Store (Zustand)
* **Что:** Центральное реактивное состояние приложения Lab.
* **Где:** `apps/lab/src/store/useChatStore.ts` (или `src/store/useChatStore.ts`)
* **Назначение:** Управление активным чатом, списком сообщений, переключением провайдеров (OpenAI, Gemini, Ollama, Groq), циклом генерации, расчётом токенов и ReAct-оркестрацией ToolHub.
* **Зависит от:** `zustand`, `Dexie (db.ts)`, `js-tiktoken`, `@lenml/tokenizer-gemini`, `toolhubSdk.ts`, `graphmemSdk.ts`.
* **Кто использует:** Все интерфейсные компоненты Lab (`ChatArea`, `ChatInput`, `Sidebar`, `ContextSidebar`, `SettingsModal`).
* **Вход:** Пользовательские сообщения, события ответа SSE-стрима, ответы от ToolHub.
* **Выход:** Реактивное состояние интерфейса, сохранение в IndexedDB.
* **Критические ограничения:** Содержит логику автономного цикла агента с ограничением задержки (`toolhubDelay`) и лимитов итераций.

---

### Компонент: Lab Local Database (Dexie.js)
* **Что:** Клиентская база данных IndexedDB.
* **Где:** `apps/lab/src/db/db.ts` (или `src/db/db.ts`)
* **Назначение:** Надёжное хранение истории чатов, деревьев сообщений с шагами инструментов (`toolSteps`) и параметров провайдеров прямо в браузере.
* **Зависит от:** `dexie`, `dexie-react-hooks`.
* **Кто использует:** `useChatStore.ts`, интерфейс Lab.
* **Вход:** Объекты диалогов и сообщений.
* **Выход:** Индексированные выборки по `chatId`, `parentId`, `createdAt`.
* **Критические ограничения:** Работает строго в браузере. Не требует серверных ресурсов.

---

### Компонент: ChatTree Module
* **Что:** Модуль работы с ветвящимися деревьями диалогов.
* **Где:** `apps/lab/src/lib/chatTree.ts`
* **Назначение:** Построение линейной цепочки сообщений от корня к выбранному листу, переключение сиблингов (альтернативных версий генерации), ветвление при редактировании сообщения.
* **Зависит от:** Чистые алгоритмы работы с деревьями (без внешних зависимостей).
* **Кто использует:** `useChatStore.ts`, `ChatArea.tsx`.
* **Вход:** Массив сообщений с `id` и `parentId`.
* **Выход:** Упорядоченный путь сообщений для передачи в контекст LLM.

---

### Компонент: Monaco CodeBlock & LaTeX Renderer
* **Что:** Модули отображения богатого контента сообщений.
* **Где:** `apps/lab/src/components/CodeBlock.tsx`, `ChatArea.tsx`
* **Назначение:** Подсветка и редактирование кода в Monaco Editor, рендеринг математических формул через KaTeX (`rehype-katex`, `remark-math`).
* **Зависит от:** `@monaco-editor/react`, `katex`, `react-markdown`.
* **Кто использует:** `ChatArea.tsx`.
* **Вход:** Сырой текст Markdown с блоками кода и формулами `$ ... $`.
* **Выход:** Высококачественный интерактивный DOM.

---

### Компонент: Voice Engine (STT / TTS)
* **Что:** Голосовой модуль ввода и синтеза речи.
* **Где:** `apps/lab/src/lib/voiceEngine.ts`
* **Назначение:** Запись голоса через Web Speech API / Push-To-Talk, потоковое озвучивание ответов с фильтрацией блоков кода и формул.
* **Зависит от:** Браузерные API `SpeechRecognition`, `speechSynthesis`, либо настраиваемые внешние HTTP эндпоинты.
* **Кто использует:** `ChatInput.tsx`, `ChatArea.tsx`.

---

### Компонент: Unified HubSDK
* **Что:** Клиентская библиотека протокола взаимодействия с ToolHub.
* **Где:** `packages/sdk/sdk.ts` (ранее `toolhub/SDK/JS/sdk.ts` и `lab/src/lib/toolhubSdk.ts`)
* **Назначение:** Парсинг ответов модели на наличие тегов `<hub>...</hub>`, безопасный парсинг JSON-параметров с автоисправлением синтаксиса, выполнение HTTP-вызовов `listTools` и `callTool`, упрощение транспортных структур ответа Fastify.
* **Зависит от:** Стандартный `fetch`.
* **Кто использует:** `apps/lab/src/store/useChatStore.ts`, сторонние агенты на Node.js/Bun/Deno.
* **Вход:** Текст ответа LLM, базовый URL ToolHub, пароль агента.
* **Выход:** Выполненный результат инструмента, очищенный текст сообщения для отображения пользователю.
