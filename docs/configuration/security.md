# Аудит безопасности и конфигурация секретов (Security & Secrets)

> **Статус документа:** Аудит безопасности  
> **Дата:** Октябрь 2026  
> **Охват:** Исходные репозитории `toolhub` и `lab`, конфигурация окружения и сетевой периметр.

---

## 1. Результаты сканирования на утечку секретов

В ходе исследования обоих репозиториев (`toolhub` и `lab`) был выполнен автоматический аудит кодовой базы, файлов конфигурации и истории Git коммитов.

* **Паттерны сканирования:** регулярные выражения для поиска токенов, приватных ключей, API-ключей провайдеров (OpenAI `sk-...`, Google Gemini `AIzaSy...`, Anthropic `sk-ant-...`, JWT токены, пароли баз данных).
* **Результат:** 
  - Реальные пользовательские API-ключи, пароли или секреты в кодовой базе **НЕ ОБНАРУЖЕНЫ** (чисто).
  - Найдены только стандартные шаблонные значения по умолчанию для локального тестирования:
    - `agentSecret = "123"` (пароль агента по умолчанию в сиде и сторе).
    - `adminPassword = "admin"` (мастер-пароль админки по умолчанию в сиде).

## 2. Анализ модели безопасности экосистемы

### 2.1. Клиентская безопасность (Lab Studio)
1. **Local-First Storage:**
   - Все ключи API (OpenAI, Gemini, Groq, OpenRouter) сохраняются исключительно в `IndexedDB` браузера пользователя.
   - Ключи **никогда не отправляются** на бэкенд ToolHub.
   - Запросы к провайдерам выполняются напрямую из браузера пользователя через `fetch` с соответствующими заголовками `Authorization: Bearer <key>`.
2. **CORS и локальные движки:**
   - Для локальных нейросетей (Ollama) требуется корректная настройка переменной `OLLAMA_ORIGINS="*"` на стороне сервера Ollama, чтобы браузер не блокировал cross-origin запросы.

### 2.2. Серверная безопасность (ToolHub Core API)
1. **Двухуровневая модель аутентификации:**
   - `x-agent-password`: заголовок для агентских операций (`GET /*`, `POST /*`, `GET /prompt`). Позволяет автономным агентам исследовать каталог и вызывать инструменты.
   - `x-admin-password`: заголовок для административных операций (`/admin/api/*`). Даёт право на создание, редактирование кода инструментов, удаление логов и управление раннерами.
2. **Изоляция выполнения скриптов (Sandboxing):**
   - Инструменты исполняются во временном каталоге ОС (`os.tmpdir()`), где создаётся уникальная директория для каждого запуска.
   - По завершении (или таймауту) временная директория удаляется.
   - Для каждого инструмента настраивается `timeoutMs` (по умолчанию 30 секунд), предотвращающий бесконечные циклы или зависание процессов.
3. **Безопасность MCP пула:**
   - Долгоживущие процессы stdio отслеживаются сервером.
   - При завершении работы сервера (`SIGINT`/`SIGTERM`) вызывается `cleanupAllPoolProcesses()`, принудительно убивающая дочерние процессы MCP.

## 3. Рекомендации для Production-развёртывания

1. При публичном развёртывании сервера в обязательном порядке изменить стандартные пароли:
   ```bash
   bun run prisma/seed.ts -- --lang=en --admin-pass=STRONG_SECRET_ADMIN --agent-pass=STRONG_SECRET_AGENT
   ```
2. Использовать HTTPS и реверс-прокси (Nginx, Caddy, Cloudflare) для шифрования трафика между браузером и сервером.
3. Использовать `.env` файл на основе безопасного шаблона `.env.example`.
